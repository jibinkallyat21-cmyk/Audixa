## MISCPA requirement list (from MIS_Req_list.xlsx)
31. The 18 categories / 54 items are kept verbatim from the Excel (including its spelling) in `src/data/misRequirements.js`. A client allocated to MISCPA sees this preset list first; once a trial balance is analysed only categories with a matching ledger (opening balance or movement) are kept. Each kept category shows the ledgers that triggered it. The auditor can remove a category or add one back, then issues the list; the client portal shows the issued list.
32. The matching rules (ledger group and name patterns in `src/utils/requirementsEngine.js`) are my reading of the category names, not from the rule book. TB item 2 (consolidated TB) is requested only when the TB has several branches/entities ("if applicable").
33. ABCPA: shows "will be provided later"; the old sample list stays underneath until supplied.
- Open: confirm the matching rules per category; whether a materiality floor should drop small balances; whether Kingdom Retail Holdings (client portal demo) should be a real MISCPA file.
34. Demo data switch (client dashboard): "Load demo data" adds Kingdom Retail Holdings LLC (MISCPA) as a file at the top of the execution team's portfolio and issues its requirement list from the demo trial balance; "Remove demo data" undoes both. It is stored in the browser, so it shows in the team portal in the same browser. Each execution tool (TB review, sampling, vouching, confirmations, GOSI/EOSB, salary, prepaid, depreciation, IFRS TB, financial statements) fills itself with its own demo data when opened while the switch is on. Tools have no client picker yet, so the demo data is not tied to one client. Queries, EL and basic-documents intake are not auto-filled.
35. Client and Execution Team portals now hold no data of their own: every client page except the Engagement Dashboard, and every team page, shows "Nothing here yet" until demo data is loaded. With demo on, the client Requirement List shows the issued MISCPA list in the existing table (ref, name, reason, status, file, action); Upload records the file and sets "Uploaded Processing". The client dashboard counts come from that list. The team Files, Dashboard KPI tiles and other pages still contain sample figures once demo is on; they are not yet driven by the demo file.
36. The client's first requirement is the trial balance. Until then the client sees only "Step 1: Upload your trial balance" with the prescribed columns (ledger name, opening, debit, credit, closing; ledger code recommended) and a downloadable format file. A file that passes goes to the audit team ("Submitted"); they approve it, which issues the requirement list built from that TB (they can first remove or add categories), or return it with a reason and the client uploads again. Demo data no longer issues a list by itself.

37. "Change categories" re-issues the list and resets review progress.
